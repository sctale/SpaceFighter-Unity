# 设计走查 · 2026-11-04（v0.20.2 现状）

> 依据：`docs/shots/android_v0202_play.png`、`art_three_ships.jpg`、`art_lowpoly_batch.jpg`、
> 以及近五版的菜单/暂停/结算实拍。结论按"玩家第一眼会不会觉得糙"排序，不按工作量排序。

## 一句话诊断

**不是某一处画得差，是三套美术语言叠在同一个画面里，而且明度关系是反的。**

- 玩家机是 **深青低模**（Polyfork，21 个分件）；
- 敌机是 **银白低模**（程序化，10 来个挤出块），亮度和玩家接近，混战时认不出自己；
- 弹幕是 **柔边圆形光斑**（PIL 时期的手绘，和低模硬边完全两种语言）；
- HUD 是 **玻璃胶囊 + 圆角描边**（IMGUI 时期），和低模的硬转折也不搭；
- 背景是 **单层渐变 + 稀疏星点**，没有层次，像一张贴图而不是"深空"。

美术迭代了三代（PIL 手绘 → 硬表面 3D → 低模），每一代只换了一部分，所以现在最刺眼的
是**接缝**，不是单个资产。

## 明度关系：本作最要命的一条

现在画面里最亮的是**敌机和敌方子弹**，玩家机是暗的。弹幕游戏必须反过来：

| 层 | 目标明度 | 现状 |
|---|---|---|
| 玩家机 | 最亮、饱和（青色身份色） | 偏暗，和背景差 15% |
| 敌机 | 中亮、按机种有色相 | 接近纯白，12 种全一个样 |
| 敌弹 | 高亮但要小于玩家 | 巨大柔光斑，视觉半径 ≈ 判定半径 ×2.5 |
| 背景 | 最暗，低饱和 | 勉强合格，但缺层次 |

**根因**：`build_from_spec()` 只把 `spec["accent"]` 用在霓虹条上，机体本体一律用
默认深色金属；而低模模式的 key 光把平面打到接近白色。等于**把敌机的色相身份全部丢了**
（`EnemyDefs` 里那 12 个 Tint 一个都没进画面），同时把亮度堆到了错误的对象上。

## 逐屏问题清单

### A. 战斗画面（P0）

1. **12 种敌机看起来是同一种**：都是银白盾形。`EnemyDefs` 的 per-kind Tint 未参与渲染。
   → 机体的 hull 用该机种 Tint 压暗 55%、饱和度保留；银白只留给精英。
2. **玩家机不"跳"**：深青压在深蓝上。→ 玩家机加 1px 亮边（轮廓光单独渲一层或材质 rim），
   并把机身明度提 12%。
3. **敌方子弹是柔边圆斑**（`bullet_enemy_orb`）：圆、软、带大光晕，与低模硬边冲突，
   视觉尺寸约是判定半径的 2.5 倍（判定 6px、看上去 15px）。
   → 重做成**菱形/八边形硬边弹**，核心亮、外圈只留 1px 暗边，整体视觉尺寸压到判定的 1.3 倍。
4. **玩家子弹是细长胶囊**，和敌弹形状接近，混战时分不清敌我。
   → 玩家弹改成**短粗的实心菱形**（同色系但形状不同），敌弹用**空心环 + 亮芯**。
5. **没有引擎/尾焰**：三艘玩家机飞起来都是"贴纸"。`ThrusterTrail` 存在但只在大招时闪。
   → 按机种挂 1–2 个持续的小尾焰（随机抖动），Boss 挂呼吸辉光。
6. **爆炸与命中反馈弱**：击杀只有一圈 Impact + 飘字；`Shake` 幅度偏小。
   → 击杀加 3–5 片碎片（用舰船剪影裁片），精英加 0.06s 白闪。

### B. HUD（P0/P1）

7. **分数底板像一张贴纸**：现在是一个 300×130 的描边矩形，四角圆角 10，压在渐变上
   有明显色差。→ 要么去掉底板、只保留顶部压暗（web 的做法），要么做成与低模一致的
   **切角八边形**（左上右下切角），别用圆角矩形。
8. **仪表带五件套重心不齐**：船体三角/护盾六边/武器环/进度轨/动作环的基线各自偏 2–6px。
9. **数字不是等宽**：SCORE 与 BEST 变化时会左右跳。→ 用等宽数字（font 里已有 tabular 支持，
   或固定位数右对齐）。
10. **动作环内文字偏大**（精准/慢速两行挤在 40px 环里），"星爆 87%" 的百分号贴边。
11. **结算页信息密度低**：10 个格子占了大半张卡，但真正有用的只有分数/评级/最远星区。

### C. 背景与氛围（P1）

12. **星区背景是一层渐变**：`ZoneSky` 有每星区的天空色，但缺**第二层**（星云/尘埃带）。
    → 每星区加 1 层大尺度噪声云（缓慢横移）+ 1 层近景亮星（视差 0.3）。
13. **星点太稀、亮度均匀**：现在约 60 颗、亮度接近。→ 分三档（暗/中/亮），暗星多、亮星少。
14. **没有"深空感"**：缺暗角与色差。→ 屏幕四角加 6% 暗角；远处星点带轻微蓝移。

### D. 动效（P1）

15. **没有持续动势**：玩家静止时画面完全不动（只有星点）。→ 背景视差常驻（0.6 px/s）。
16. **公告入场只有位移**：没有缩放/闪白，节奏偏"网页"。
17. **受击反馈不足**：受创只有红闪 + 抖屏，没有"画面短暂失真/降饱和"。

### E. 一致性（P1/P2）

18. **三艘玩家机细节密度差一档**：interceptor 21 个分件，另两艘十几个挤出块。
    → 给棱镜/蜂群补 3–5 个装甲分件（引擎环、进气口、装甲缝），至少让"零件感"接近。
19. **补给箱仍是圆角胶囊 + 圆图徽**，和低模方硬风格冲突。→ 改成切角方箱 + 硬边图徽。
20. **字体**：标题用 CJK Regular 假粗，笔锋和低模的机械感不搭（可接受，优先级最低）。

## 视觉契约（后续所有改动的验收标准）

1. **明度阶梯**：玩家 > 敌弹 > 敌机 > 背景，四层之间至少差 12% 明度。
2. **色语义**：玩家=青、棱镜线=玫、蜂群线=金、敌机=各自 Tint、Boss 环=各自色。
   同屏最多 4 个饱和色相。
3. **形状语言**：一律硬边（切角/菱形/八边形），禁止柔边圆形光斑；
   光晕只能作为**低透明外发光**（≤0.45），不能改变轮廓。
4. **视觉尺寸 ≤ 判定 ×1.4**：任何弹体的可见外缘不得超过判定的 1.4 倍，避免"看着大、判定小"。
5. **玩家永远最容易被找到**：任何时刻，玩家机是画面里对比度最高的对象。

## 建议的推进顺序

| 批次 | 内容 | 影响 | 工作量 |
|---|---|---|---|
| **P0-1** | 敌机按 Tint 上色（12 张重渲）+ 玩家加轮廓光 | 直接解决"全屏一个样" | 一轮渲染 |
| **P0-2** | 敌弹/玩家弹重做形状（硬边菱形 / 空心环），视觉尺寸压到判定 1.4× | 弹幕一眼分清敌我 | 一轮渲染 + 1 处参数 |
| **P0-3** | 分数底板改切角八边形（或去掉），仪表带基线对齐 | HUD 不再像"贴纸" | 纯 UI |
| **P1-1** | 背景加第二层星云 + 三档星点 + 常驻视差 | 画面"活"起来 | 1 个新组件 |
| **P1-2** | 玩家/Boss 持续尾焰与呼吸辉光；击杀碎片 | 打击感 | 2 个组件 |
| **P2** | 棱镜/蜂群补分件、补给箱方箱化、数字等宽 | 一致性 | 各半天 |

## 怎么验收（不靠"感觉好点了"）

- 每批改动出 **同机位前后对比图**（540×960 与 1080×1920 各一张）；
- 用像素取样验证明度阶梯：玩家机平均亮度 > 敌弹 > 敌机 > 背景，各差 ≥12%；
- 弹体：`check_art` 增一条「视觉半径 / 判定半径 ≤ 1.4」；
- 门禁保持 434+ 条全绿，真机 `E/Unity` = 0。
